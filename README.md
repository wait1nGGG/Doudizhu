# 斗地主

单机斗地主，**纯静态、零依赖、零构建** —— 直接用浏览器打开 `index.html` 即玩。

```
index.html    页面结构 + 全部样式（内联）
doudizhu.js   全部逻辑：牌型判定、AI、渲染、事件（单个 IIFE）
```

## 玩法

- 3 人局：你 + 电脑A + 电脑B。抢地主 → 定地主 → 出牌。
- 抢地主人数为 2 时用**石头剪刀布**定地主，为 3 时先**手心手背**淘汰一人再猜拳。
- 点牌选中（也可按住拖动多选），「提示」给一手推荐，「不出」在非领出时可点。
- 右下角 **OP** 面板是作弊开局，可固定刷出炸弹 / 飞机 / 王炸等牌型，玩家必当地主先手。
- 右下角 **记牌器** 显示的是「外面还剩几张」= 总数 − 已出 − 我的手牌；剩 4 张时标红提示可能有炸弹。
  （两个浮层都比按钮宽，同时展开会互相遮挡，所以展开一个会自动收起另一个。）
- 左下角可切换 **简单 / 普通 / 困难**，切换后立即重开一局。

## 界面

配色取自「毡面绿 + 金 + 深色底」的棋牌组合，质感走轻拟物：木质外框、绒面毡桌、多层阴影、按压缩放。
颜色、圆角、动效时长都收在 `index.html` 顶部的 `:root` 里，改一处即可整体换肤。

几条自己踩过的坑，改样式时注意：

- 牌桌由 `#game-container` 铺木纹、`::before` 用 `inset:var(--rail)` 把中间"挖"成毡面。
  **不要再给 `::before/::after` 加 `inset:0` 的背景**，否则会像早期版本那样整块盖住毡面。
- 手牌区用 `padding-bottom: var(--hud-clear)` 抬到底部两组 HUD 之上，否则最左边几张会被压住。
- 图标一律用内联 SVG（`<symbol>` + `<use>`），不用 emoji：emoji 跨平台字形不一致，也没法跟着文字颜色走。
  猜拳的 ✊✌️✋ 和手心手背的 ✋✊ 是游戏内容不是图标，保留。

## 牌型

单张、对子、三张、三带一、三带二、顺子（≥5 张，不含 2 和王）、连对（≥3 对）、
飞机（≥2 个连续三张）及其带单/带对、四带二单、四带两对、炸弹、王炸。

## AI 设计

目标是「像中等水平玩家」，所以走**静态规则 + 有限搜索**的路线，不做深度搜索。
三个环节：**拆牌 → 牌组评分 → 策略栈**。

**拆牌**（`splitHand`）按固定优先级把一手牌拆成「一次能出掉」的牌组：
王炸 → 炸弹 → 飞机 → 顺子/连对 → 三张 → 对子 → 单张，最后给三张/飞机配最小的带牌。
顺子与连对存在先后顺序之争（`3344556789` 该拆连对还是顺子），因此两种顺序各算一遍取高分。

**评分**（`scoreGroups`）给每个牌组打分（越能管牌、越难被管，分越高），
再减去轮次惩罚：`Σ牌组分 − P(组数) × 组数`，P 随组数递减。
王/2/炸弹那一轮总能出去，不计入轮次。

**记牌与赢牌路径**：用「总数 − 已出 − 我的手牌」推出外面的余牌，
判断每个牌组是否还可能被管住。若会被管的牌组 ≤1 个，就先把不会被管的出完、
把唯一会被管的那组留到最后 —— 因为出完最后一手即获胜，这是一条**必胜路线**。
残局里 AI 靠这条规则收官，是它最难对付的部分。

**接牌**会区分：是不是队友的牌、对手还剩几张、动这手牌会不会拆散自己的顺子/对子/炸弹。
对手 ≤2 张时不计代价拦截（优先不用炸弹），队友 ≤2 张时让牌。

留了软采样（top5 候选按分数加权抽签），所以 AI 不会每局都走同一条线。

### AI 强度

三档难度主要靠 `followBase`（抢不抢牌权）拉开，温度只做微调。
下表是各档 vs **重写前旧 AI** 的团队胜率（每档 3000 局，A 队一半当地主一半当农民）：

| 难度 | 对旧 AI 胜率 |
|---|---|
| 简单 | 45.6% |
| 普通 | 60.5% |
| 困难 | 74.1% |

作为参照，同一测试下旧 AI 打自己是 50%。所有参数集中在 `doudizhu.js` 的 `AI` 与
`DIFFICULTY` 两个对象里，想调风格改这一处即可。

## 实现注意：异步与打断

一局的所有延迟动作（AI 出牌、发牌、猜拳、结算…）都必须走 `Game._schedule()`，
**不要直接写 `setTimeout`**。原因：

「重新开始」和「切换难度」是丢掉旧的 `Game` 实例、新建一个。但旧实例已经排进
`setTimeout` 的回调不会随之消失，它们跑起来会调用 `renderAll(this)`，把**上一局的画面
重新画回屏幕**，接着又通过 `_executePlay → _schedule(() => this._aiTurn())` 继续把旧局打下去，
看起来就是「画面跳回上一把，再跳回新一局」。

`_schedule` 是唯一的调度入口，因此打断只需要在这一处做：回调执行前检查 `this._alive`，
`resetGame()` 调 `destroy()` 把 `_alive` 置 false 并清空定时器队列。

## 自测

`doudizhu.js` 是单个 IIFE、不导出任何东西。测试时把 `RENDERER` 标记之前的纯逻辑切出来
`new Function` 求值即可无头运行（不需要 jsdom），可用来跑规则单测、拆牌不变式校验、
自对弈与新旧 AI 对抗。
